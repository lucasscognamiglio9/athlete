# Athlete Onboarding

Build the smallest athlete model that can support the next real coaching decision.

Read [`../../shared/coach-core.md`](../../shared/coach-core.md) and [`../../shared/canonical-file.md`](../../shared/canonical-file.md) completely before acting.

## 1. Establish the current state

Determine whether a canonical file already exists and classify Google Drive with the complete capability taxonomy in the shared canonical-file reference. An existing file may be read during discovery; its structure does not dictate the questions.

Continue when the source of durable state and current capability are explicit.

## 2. Grill only the decision

Ask for information that can change the current decision: objective, current activities or practice context when relevant, experience, availability, practical constraints, preferences, existing training and history, and desired coaching depth.

Classify each unknown as blocking, deferrable, or optional. Ask one reflective or dependent question at a time, or group up to three independent factual questions. Ask permission before a sensitive or long branch. Accept partial answers and skips; pause only the dependent decision. Stop when the next answer is unlikely to change the current decision.

Continue when blocking information is resolved or the dependent decision is explicitly paused.

## 3. Choose one canonical-file action

- Reuse a compatible existing file.
- Preview the minimum in-place transformation of an incompatible file and wait for authorization.
- Create one new file after discovery when none exists.

Shape the four logical blocks to the athlete. Include only fields justified by current training and decisions.

Continue when the athlete has authorized any required creation or structural change.

## 4. Persist and verify

Write the resolved athlete fields and canonical structure. Read back every affected field and tab through the same interface. Keep unresolved data marked by quality instead of filling it from assumptions.

Continue only when the same spreadsheet ID contains the verified result; otherwise report the exact unverified state.

## 5. Hand off clearly

Summarize what Athlete now knows, what remains deliberately open, the canonical-file status, and the next useful coaching action. Keep the answer shorter than the discovery that produced it.

If discovery paused before a canonical file existed and a later conversation resumes it, request a brief recap instead of reconstructing durable details from Memory or chat history.

Finish when another Athlete skill can act from the verified canonical state without reconstructing the athlete from Memory or chat history.
